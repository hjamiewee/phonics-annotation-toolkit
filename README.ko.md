# phonics-annotation-toolkit

[English](README.md) | **한국어**

파닉스 교재 지문을 주석하는 파이프라인입니다. 두 가지를 보여줍니다.

- **데이터에서 에셋까지 이어지는 자동화 워크플로.** 지문과 사람 판정 파일을 넣고 명령 하나를 실행하면, 주석된 낱말 표 전체와 레슨 타깃 판정, 음성·이미지 에셋 목록이 만들어집니다. 모든 판정은 출처를 추적할 수 있고 다시 돌려도 같은 결과가 나옵니다.
- **두 축 데이터 모델.** 낱말을 **Token 축**(어떻게 소리 나는가)과 **Lemma 축**(무엇을 뜻하는가)으로 나눕니다. Token 축은 **음성 에셋**을, Lemma 축은 **이미지 에셋**을 만듭니다.

| | 실무 프로젝트 | 이 저장소 |
|---|---|---|
| 범위 | 교재 시리즈 2종, 레벨 3개 | 예시 레슨 6개 |
| 낱말 출현 | 약 52,000건 | 100건 (27줄) |
| 문맥별 뜻 판정 | 약 33,000건 | 6건 |
| 소리 키 | 약 5,400개 | 54개 |
| 기간 | 4개월 | — |
| 데이터 | — | 이 저장소용으로 새로 작성. 두 축이 갈리는 낱말과 경계 사례처럼 실무와 같은 경우를 확인할 수 있도록 구성 |

> 이 저장소는 실무에서 설계·운영한 코퍼스 구축 경험을 바탕으로 **처음부터 새로 작성한** 데모입니다.
> 실제 교재 문장, 회사 코드, 회사 데이터는 들어 있지 않습니다. 예시 문장은 모두 직접 지은 것입니다.

## 배경

파닉스 교재는 "이번 레슨에서 배우는 철자-소리 규칙"을 중심으로 짜여 있습니다.
교재 콘텐츠를 디지털화하려면 지문 속 낱말 하나하나에 대해 다음을 알아야 합니다.

- 이 낱말이 **어떻게 소리 나는가**: 철자-소리 대응(GPC), 음절, 녹음 파일
- 이 낱말이 **무엇을 뜻하는가**: 품사, 원형, 의미 번호, 삽화
- 이 낱말이 **이 레슨의 타깃인가**: 레슨이 가르치는 GPC·형태·어휘 관계에 맞는가

실무 프로젝트에서는 문맥별 뜻 판정을 결정 파일에 쌓아 재현 가능하게 적용했고,
레슨 타깃 판정, 고정된 소리 번호, 에셋 목록은 모든 행에 대해 자동으로 만들었습니다.
이 저장소는 그 데이터 모델과 워크플로를 작은 예시 데이터로 재현합니다 (규모는 위 표 참고).

## 작동 방식

```
data/lines.tsv             지문 줄
data/lessons.tsv           레슨 타깃
data/decisions/, lexicon/  사람 판정: 대표값, 문맥 판정, GPC 분해
        │
        ▼
python -m phonics_toolkit          (명령 하나, 기본은 미리보기)
        │
        ├── out/words.tsv          모든 낱말 출현, 두 축, 모든 판정
        ├── out/word_gpc.tsv       소리 키별 GPC 분해
        ├── out/word_sense.tsv     쓰인 뜻 사전
        ├── out/aud_assets.tsv     음성 에셋     ← Token 축
        └── out/img_assets.tsv     이미지 에셋   ← Lemma 축
```

- **판정은 사람이, 적용은 파이프라인이.** 사람이 판정을 결정 파일에 적습니다. 문맥에 따라 읽기가 달라지는 낱말은 문맥 키 `(Line_ID, Seq)`로 적습니다. 코드는 추측하지 않고, 판정이 없는 것은 미해결로 보고합니다.
- **모든 판정에 출처가 남습니다.** 행마다 뜻과 소리가 대표값, 문맥 판정, 규칙 중 어디서 왔는지 적혀 있어서(`sense_source`, `sound_source`), 자동 판정과 사람 판정을 언제나 구분할 수 있습니다.
- **그 뒤 단계는 모두 자동입니다.** 소리 번호, 녹음 번호, 굴절 라벨, 레슨 타깃 판정, 두 에셋 목록을 모든 행에 대해 계산합니다.
- **변경은 믿지 않고 검사합니다.** 스냅샷 테스트는 한 칸이라도 바뀌면 실패하고, 뒤에 붙이기만 하는 대장 덕분에 번호가 실행마다 바뀌지 않습니다.

단계별 입력·규칙·명령은 [처리 단계](docs/ko/workflow.md)에 있습니다.

## 두 축: Token → 음성, Lemma → 이미지

낱말의 소리와 뜻은 일대일로 대응하지 않습니다.

| 예 | 철자 | 소리 | 뜻 |
|---|---|---|---|
| `read` (읽다 / 읽었다) | 1 | 2 (/rid/, /rɛd/) | 1 |
| `bow` (리본 / 인사 / 절하다) | 1 | 2 (/boʊ/, /baʊ/) | 3 |
| `to` · `too` · `two` | 3 | 1 (/tu/) | 3 |

그래서 낱말 출현 하나에 축마다 키를 하나씩 붙입니다.

```
                  Word (지문 속 낱말 출현 하나)
                 /                          \
   Token 축 — Token-a                      Lemma 축 — p.Lemma-s
   (소리)  read-1, read-2, bow-1 ...       (뜻)  v.read-1, n.bow-2 ...
        │                                        │
   GPC 분해 (글자·소리·음절·위치)              뜻 사전
        │                                        │
   음성 에셋: 발음 하나                        이미지 에셋: 뜻 하나(+형태)
   = 녹음 하나 (Aud_ID)                        = 이미지 하나
```

자세한 내용은 [데이터 모델](docs/ko/data_model.md)에 있습니다. 용어는 [용어표](docs/glossary.md)를 참고하세요.

## 결과물

예시 데이터의 실행 결과입니다. 같은 낱말을 두 축이 서로 다르게 나눕니다.

**음성 에셋 (Token 축)**: 발음 하나에 녹음 하나. 철자가 달라도 같이 씁니다.

| aud_id | 발음 | 소리 키 (Token-a) | 낱말 |
|---|---|---|---|
| A00028 | tu | to-1, too-1, two-1 | prep.to, adv.too, num.two |
| A00011 | rɛd | read-2, red-1 | v.read (과거), adj.red |
| A00034 | rid | read-1 | v.read (현재) |
| A00044 | boʊ | bow-1 | n.bow (리본) |
| A00047 | baʊ | bow-2 | n.bow (인사) |

**이미지 에셋 (Lemma 축)**: 뜻 하나에 이미지 하나. 형태가 그림을 바꾸면 다시 나눕니다.

| image_key | 뜻 | 표면형 |
|---|---|---|
| v.read-1 | 읽다 | read (현재·과거) |
| n.bow-1 | 리본, 나비매듭 | bow |
| n.bow-2 | (고개 숙여 하는) 인사 | bow |
| n.cat-1 | 고양이 | cat |
| n.cat-1.pl | 고양이 (여러 마리) | cats |

`read`는 **녹음은 2개, 이미지는 1개**가 필요하고, `to`·`too`·`two`는 **이미지는 3개, 녹음은 1개**가 필요합니다.
두 축을 키 하나로 묶으면 에셋이 중복되거나 빠집니다.

## 더 읽을거리

- [판정 기준과 경계 사례](docs/ko/design_decisions.md): 애매한 사례를 어떻게 판정했는지 근거와 함께 정리했습니다. 예: `in a dish`와 `in the sun`의 `in`을 나눈 이유, `take a bow`를 구로 묶지 않은 이유.
- [해독 가능성 분석](docs/ko/decodability.md): 레슨마다 지금까지 배운 GPC만으로 읽을 수 있는 지문 낱말의 비율과, 읽지 못하게 막는 GPC를 구합니다. 예시 커리큘럼에서는 레슨 순서의 빈틈을 찾아냅니다. 짧은 i를 아직 가르치지 않아 sh 레슨의 해독 가능 비율이 13%에 그칩니다.

## 저장소 구성

```
├── README.md / README.ko.md
├── docs/
│   ├── glossary.md        # 한국어·영어 용어표
│   ├── en/                # 영어 문서
│   └── ko/                # 한국어 문서
├── data/
│   ├── lessons.tsv, lines.tsv   # 예시 입력 (레슨, 지문 줄)
│   ├── decisions/         # 사람 판정: 구 목록, 대표값, 문맥 판정, 소리 규칙
│   └── lexicon/           # 뜻 사전, GPC 분해, 낱말 목록
├── registry/              # 뒤에 붙이기만 하는 대장 (소리 번호, 녹음 번호, Word_ID)
├── src/phonics_toolkit/   # 파이프라인 코드
├── tests/                 # 단위 테스트, 재현 검사 (snapshots/)
└── analysis/              # 분석 가정 (기초 GPC 목록)
```

## 실행

```bash
python -m venv venv
source venv/bin/activate
pip install -e ".[dev]"
python -m pytest

# 전체 단계 실행: 요약 보기 → 결과 파일 쓰기 (out/)
python -m phonics_toolkit
python -m phonics_toolkit --write

# 해독 가능성 분석
python -m phonics_toolkit.decodability
```
